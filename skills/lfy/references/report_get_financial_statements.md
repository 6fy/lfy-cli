# get_financial_statements — GTM 建议财务报表

## 接口说明

按 **GTM（产品线/市场）** 查看当前财年 **12 个月** 的建议财务报表。每个月都会返回一行数据；某月没有数据时，金额显示为 0，但 12 行不会少。

报表里各指标含义：

- **总收入**：系统根据商机里的**已签单**和**预测签单**自动汇总，不同月份规则不同（见下文）。
- **毛利、净利**：来自企业在「GTM 建议财务报表」里已维护的配置数。
- **总成本、总费用、毛利率、净利率**：由上面几项自动推算，无需单独配置。

**权限**：需有商机**列表查看**权限；否则无法查询。

## 如何确定要查哪个 GTM

请求里必须带上 `gtm_id`（GTM 的数字编号）。

1. 若用户已明确 GTM 名称（如「核心厂商」），先执行：
   ```bash
   lfy-cli customer get_gtms '{}'
   ```
2. 在返回列表里找到名称匹配的项，取其 `gtm_id`。
3. 若名称对应多个 GTM，或用户表述不清，需请用户确认后再查。

> **硬规则**：未取得 `gtm_id` 前，**禁止**用 `{}` 调用本命令（会返回 `缺少 gtm_id 参数`）。务必先 `lfy-cli customer get_gtms '{}'` 取到 `gtm_id`，或向用户确认 GTM 后再查。

## 请求示例

```bash
lfy-cli report get_financial_statements '{"gtm_id": 24685820686}'
```

### 请求体字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `gtm_id` | number | 是 | 要查询的 GTM 编号 |

## 返回示例（成功）

```json
{
  "code": 200,
  "data": {
    "name": "当前GTM建议财务报表",
    "gtm_name": "核心厂商",
    "monthly": [
      {
        "month_index": 1,
        "start_date": "2026-01-01",
        "end_date": "2026-01-31",
        "total_revenue": 100.00,
        "total_cost": 60.00,
        "total_expense": 15.00,
        "gross_profit": 40.00,
        "gross_profit_margin": "40%",
        "net_profit": 25.00,
        "net_profit_margin": "25%"
      }
    ]
  }
}
```

`monthly` 固定 **12 条**，对应当前财年的第 1～12 月；`gtm_name` 为 GTM 名称，便于向用户展示。

## 字段说明（面向用户怎么讲）

### 顶层

| 字段 | 向用户怎么说 |
| --- | --- |
| `name` | 报表名称，固定为「当前GTM建议财务报表」 |
| `gtm_name` | 所查 GTM 的名称 |
| `monthly` | 按月的 12 行明细 |

### 每月一行（monthly）

| 字段 | 向用户怎么说 |
| --- | --- |
| `month_index` | 财年第几个月（1～12） |
| `start_date` / `end_date` | 这一统计月的起止日期 |
| `total_revenue` | **建议总收入**（见下节计算规则） |
| `gross_profit` | **毛利**（企业已配置） |
| `net_profit` | **净利**（企业已配置） |
| `total_cost` | **总成本**（由收入与毛利推算） |
| `total_expense` | **总费用**（由毛利与净利推算） |
| `gross_profit_margin` | **毛利率**，如 `40%` |
| `net_profit_margin` | **净利率**，如 `25%` |

推算关系（向用户解释时可简述）：

- 总成本 = 总收入 − 毛利  
- 总费用 = 毛利 − 净利  
- 毛利率 = 毛利 ÷ 总收入  
- 净利率 = 净利 ÷ 总收入  
- 总收入为 0 时，两个比率显示为 `0%`

## 总收入怎么算（向用户解释时使用）

系统会把财年里的每个月分成三类，**总收入**的统计方式不同：

| 月份 | 怎么理解 | 总收入包含什么 |
| --- | --- | --- |
| **已过去的月份** | 这个月已经完全结束 | 只统计该月内**已经签单**的金额 |
| **当前这个月** | 正在进行中的自然月 | **两部分相加**：<br>① 从**本月 1 号到今天就为止**，已经签单的金额<br>② 从**明天到本月最后一天**，仍在预测中的签单金额 |
| **还没到的月份** | 未来月份 | 只统计该月**预测签单**的金额 |

### 当前这个月，举例说明

假设今天是 5 月 28 日，在查 5 月这一行时：

- 先加：5 月 1 日～5 月 28 日之间，所有**已签单**的金额  
- 再加：5 月 29 日～5 月 31 日之间，所有**预测签单**的金额  
- 两者之和 = 5 月的 **建议总收入**

若今天已是某月最后一天，则没有「明天到月末」的预测段，该月总收入就等于「月初到今天」的已签单合计。
